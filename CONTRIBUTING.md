# Участие в разработке

## Процесс

1. Создайте отдельную ветку от `main`: `feat/...`, `fix/...` или `refactor/...`.
2. Изменяйте код и по возможности добавляйте/исправляйте тесты в `tests/`.
3. Запустите `npm test` и проверьте изменение вручную в Discord, если оно связано со звуком или интерфейсом.
4. Создайте Pull Request с описанием поведения до и после, способом тестирования и рисками.
5. После проверки объедините PR в `main`. Не публикуйте релиз для каждого промежуточного коммита.

## Коммиты: Conventional Commits 1.0.0

Шаблон: `type(scope): imperative summary`

- `feat(audio): add speech activity filter` — новая функция
- `fix(audio): preserve gain during silence` — исправление
- `refactor(core): separate gain controller` — изменение структуры без изменения поведения
- `test(audio): cover short noise bursts` — тесты
- `docs: describe manual volume baseline` — документация
- `ci: run Node.js tests on pull requests` — CI
- `chore: update repository metadata` — обслуживание

Тема — краткая, однострочная, на английском; тело по желанию раскрывает мотивацию и изменение. Несовместимые изменения обозначаются `!` или разделом `BREAKING CHANGE:` в теле. Не придумывайте `feat` для исправлений и не используйте `refactor`, если меняется поведение.

## Что не отправлять в репозиторий

- Секреты и токены; файлы `.env`, содержащие секреты.
- Файлы и настройки личного Discord-аккаунта.
- `node_modules/`, временные файлы, дампы звонков.
- Не проверенные на личные данные логи и диагностические записи.

## Релизы

Первый кандидат стабильной версии — после проверки ручных сценариев из [дорожной карты](./docs/ROADMAP.md). Релизное вложение — только `VoiceNormalizer.plugin.js`, без тестов.
